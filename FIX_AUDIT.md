## Schema Migration & Backwards Compatibility

- **New sessions (`schema_version: 2`)** written by `POST /api/session/log` store:
  - Canonical lowercase UUID `session_id`
  - Nullable measured metrics (`wpm`, `word_count`, `capture_seconds`, `speech_status`, `wpm_source`, `fillers`, `posture`, `posture_samples`, `shoulder_tilt`, `eyeContact`, `eye_contact_ratio`, `camera_samples`, `emotion`, `emotion_counts`, `avg_volume`, `avg_pitch`, `dominant_tone`, `tone_counts`, `audio_windows`, `voiced_windows`, `audio_finalized`, `audio_sample_rate`, `timeline`)
  - `client_payload_sha256` for idempotent retry detection
- **Legacy sessions (`schema_version` absent / `1`)** in `data/raw/session_*.json`:
  - Remain readable via `GET /api/report/{session_id}` and `GET /api/sessions` (`is_readable_session_id` accepts both UUIDs and legacy `session_[a-z0-9]{1,64}` IDs).
  - `_extract_session_metrics()` prefers `wpm` when present and only falls back to `avg_wpm` if `schema_version < 2` and `wpm` is absent.
  - Missing `timeline` arrays default to `[]`, which `ReportPage.js` renders honestly as `"No session timeline recorded"`.

## Honest Limitations Impossible to Fix Without Data or Hardware

1. **Vocal Tone Model (`backend/models/tone_model.joblib`):**
   - Trained on 480 synthetic 1.5 s waveforms generated from sine harmonics + amplitude envelopes (`backend/ml/train_tone_model.py`), not real human speech recordings. Code fixes ensure it now receives properly resampled 16 kHz, 1.5 s voiced windows and returns `null` on silence, but real-world tone classification accuracy requires collecting and labeling real microphone recordings.
2. **Performance Score Regressor (`backend/models/performance_model.joblib`):**
   - Trained on 78 historical session JSONs whose target label was generated by the heuristic formula `compute_target_score()` in `backend/ml/train_performance_model.py` (which itself learned from noisy v1 logs containing interim-transcript WPM inflation and loudness-based `avg_wpm`). While inference now matches training preprocessing and withholds scores when `wpm` or `posture` is unmeasured, true public-speaking quality validation requires human-rated training sessions.
3. **Camera Alignment vs. True Eye Gaze:**
   - Nose horizontal centering (`Math.abs(nose.x - 0.5) < 0.08`) only measures whether the speaker's face is centered in the camera frame, not where their pupils are looking. It is now labeled `Camera Alignment (approx.)` in the UI while preserving the `eyeContact` feature key expected by the saved `OneHotEncoder`.
